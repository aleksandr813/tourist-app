# Техническое задание

## Мини-приложение MAX «Маршруты»: поиск и создание туристических маршрутов по городам

Трек хакатона: «Досуг и развлечения»

Документ описывает текущее состояние проекта. У каждого экрана и функции указан статус:

- **Реализовано** - работает в текущей версии;
- **Частично** - основная часть работает, недостающее перечислено;
- **Не реализовано** - запланировано, но ещё не сделано.

---

## 1. Общее описание продукта

**Проблема:** человек, который приезжает в город на 1-2 дня (или житель, который хочет провести выходные иначе), собирает маршрут из разрозненных источников: отзывов, карт, блогов. Заранее понять, во сколько обойдётся день, сложно.

**Решение:** мини-приложение внутри мессенджера MAX, в котором:

- можно найти готовые туристические маршруты по выбранному городу с общей стоимостью;
- каждый маршрут - это последовательность мест (музеи, парки, кафе, смотровые площадки) с ценой посещения каждого места;
- пользователи сами создают маршруты: отмечают точки на карте и заполняют информацию о местах вручную;
- маршруты можно лайкать и сортировать по популярности.

**Пользователь:** житель или турист, который приехал в незнакомый город на 1-2 дня или планирует выходные и хочет получить готовый маршрут с понятной стоимостью, но тратит время на сбор информации о местах и ценах.

---

## 2. Пользователь и авторизация

Мини-приложение открывается внутри мессенджера MAX через бота. Отдельной регистрации и гостевого режима нет.

**Реализовано:**

- id пользователя берётся из MAX Bridge: `window.WebApp.initDataUnsafe.user.id`. Скрипт MAX Bridge (`https://st.max.ru/js/max-web-app.js`) подключён в `client/public/index.html`, логика находится в сервисе `client/src/services/Max/Max.js`;
- id сохраняется в Store (`userId`) при запуске и используется как автор маршрута и владелец лайков;
- MAX передаёт данные пользователя в адресе страницы (`#WebAppData=...`), поэтому в обычном браузере id нет. В режиме разработки (`npm start`) вместо него подставляется тестовый id `dev-user` (`DEV_USER_ID` в `Config.js`). В продакшен-сборке вне MAX лайки и публикация недоступны, у кнопки лайка есть подсказка «Лайки доступны в приложении MAX».

**Режим тестирования:** если на сервере включена настройка `ROUTES.ALLOW_ANONYMOUS` (переменная окружения `ALLOW_ANONYMOUS_ROUTES=true`), маршрут можно опубликовать без id пользователя, автором записывается `anonymous`. По умолчанию настройка выключена, и запрос без id получает ошибку 11 «Ошибка авторизации». Лайки без id недоступны в любом режиме.

**Проверка подписи (реализовано):**

- клиент отправляет строку `window.WebApp.initData` в заголовке `X-Max-Init-Data` каждого запроса;
- если на сервере задан `BOT_TOKEN`, менеджер `modules/auth/AuthManager.js` проверяет подпись по алгоритму из документации MAX:
  - параметры, кроме `hash`, сортируются по ключу и объединяются в строку `key=value`, разделённую переводами строк;
  - секретный ключ: `HMAC-SHA256("WebAppData", BOT_TOKEN)`;
  - подпись: `HMAC-SHA256(секретный ключ, строка)` в hex, сравнивается с `hash`;
  - данные старше 24 часов не принимаются;
- при заданном `BOT_TOKEN` id из тела запроса и параметров игнорируется, пользователь берётся только из проверенных данных. Без подписи лайк получает ошибку 401;
- если `BOT_TOKEN` не задан (локальная разработка), сервер доверяет id из запроса и сообщает об этом в логе при запуске.

## 3. Функциональные требования

### 3.1 Экран запуска: выбор города

**Статус: Реализовано** (кроме выбора на карте).

Открывается сразу при запуске.

**Элементы:**

- заголовок «Выберите город» и подзаголовок;
- поле ввода с подсказками (компонент `StartPage/CitySearch`):
  - сначала показываются города, название которых начинается с введённого текста, затем те, где текст встречается внутри названия;
  - не более 8 подсказок, «е» и «ё» не различаются;
  - под названием города указан регион, чтобы различать одноимённые города (например, три города Советск);
  - управление стрелками, Enter и Esc, на телефоне касанием;
  - если ничего не найдено, показывается «Город не найден»;
- автоматический выбор ближайшего города:
  - геопозиция берётся через `navigator.geolocation` (сервис `client/src/services/Geo/Geo.js`). В MAX Bridge метода геолокации нет;
  - ближайший город считается по расстоянию на сфере до центра города из базы и подставляется в поле с подписью «Ближайший к вам город»;
  - если пользователь выбрал город раньше, чем пришла геопозиция, его выбор не перезаписывается;
  - если доступ к геопозиции запрещён, поле остаётся пустым;
- кнопка «Далее», активна только когда город выбран из подсказок;
- пока города загружаются, поле неактивно и показывает «Загружаем города...». При ошибке показывается «Не удалось загрузить список городов» и кнопка «Повторить»;
- если приложение открыто по ссылке «Поделиться» (`startapp=route_<guid>`), после загрузки городов сразу открывается экран этого маршрута (3.3), а выбранным городом становится город маршрута.

**Не реализовано (Could Have):** кнопка «Выбрать на карте».

### 3.2 Список маршрутов города

**Статус: Частично.**

**Реализовано:**

- кнопка «Сменить город» и заголовок «Маршруты - <город>»;
- переключатель сортировки: «Новые» (по дате создания) и «Популярные» (по числу лайков, при равенстве сначала новые);
- карточки маршрутов: обложка с подписью автора фото, название, общая цена («Бесплатно», если 0), кнопка лайка с числом лайков, кнопка «Подробнее»;
- пагинация по 10 маршрутов: кнопки «Назад» и «Вперёд» и номер страницы («1 из 2»). Если страница одна, кнопки скрыты;
- номер страницы и сортировка хранятся в Store: после просмотра маршрута пользователь возвращается на ту же страницу. При смене города страница сбрасывается на первую;
- пустое состояние «Пока нет маршрутов в этом городе»;
- во время загрузки показывается «Загружаем маршруты...», при ошибке «Не удалось загрузить маршруты» и кнопка «Повторить»;
- ответ от устаревшего запроса игнорируется, поэтому быстрое переключение сортировки или страниц не приводит к неверному списку;
- плавающая кнопка «+» открывает создание маршрута (3.6).

**Не реализовано:**

- иконка перехода в личный кабинет (3.7);
- длительность маршрута на карточке;
- фильтры по категориям и длительности (Could Have).

### 3.3 Экран маршрута

**Статус: Частично.**

**Реализовано:**

- кнопка «К маршрутам»;
- обложка с подписью автора и лицензии фото, название, описание автора, общая цена;
- дата публикации и пометка «Цены примерные и указаны автором маршрута»;
- кнопка лайка;
- кнопка «Поделиться» (показывается внутри MAX, если задано имя бота): отправляет в чат MAX текст и ссылку `https://max.ru/<бот>?startapp=route_<guid>` через `WebApp.shareMaxContent`. Получатель открывает ссылку и сразу попадает на маршрут;
- кнопка «Карта маршрута» (неактивна, если в маршруте нет мест);
- пронумерованный список мест в порядке посещения: номер, фото, название, цена;
- тап по месту открывает карточку места (3.4);
- если места не загрузились, показывается «Не удалось загрузить места маршрута».

**Не реализовано:**

- имя автора (сейчас хранится только id пользователя MAX);
- длительность и группировка мест по дням («День 1», «День 2»).

### 3.4 Карточка места

**Статус: Частично.**

Открывается модальным окном по тапу на место в списке или на метку на карте.

**Реализовано:** фото с подписью автора и лицензии, номер места в маршруте, название, цена, описание, кнопка «Показать на карте» (открывает карту маршрута с центром на этом месте), закрытие по крестику или тапу вне окна.

**Не реализовано:** категория места (кафе, музей, парк и т.д.), галерея из нескольких фото.

### 3.5 Карта маршрута

**Статус: Реализовано.**

- карта 2GIS (MapGL JS API) на весь экран;
- метки с номерами в порядке посещения;
- пешеходный маршрут между точками через плагин `@2gis/mapgl-directions`;
- при открытии карта подгоняет масштаб так, чтобы были видны все точки. Если карта открыта из карточки места, центр на этом месте;
- кнопка «Скрыть маршрут» / «Показать маршрут»: линия маршрута мешает нажимать на метки, поэтому её можно выключить. Метки при этом остаются;
- тап по метке открывает карточку места;
- кнопка «К маршруту».

На экранах уже 420 px кнопка переключения маршрута переезжает вниз, чтобы не пересекаться с кнопкой «К маршруту».

### 3.6 Создание маршрута

**Статус: Частично.**

**Шаг 1. Общая информация** (`CreateRoutePage`)

- обложка маршрута (JPEG, PNG или WebP);
- название маршрута (обязательно);
- город (подставляется выбранный, изменить нельзя);
- описание (обязательно);
- длительность 1 или 2 дня (поле есть, но пока не сохраняется);
- кнопка «Далее» активна, когда заполнены название и описание. Черновик сохраняется в Store (`route`), при возврате на шаг поля восстанавливаются.

**Шаг 2. Расстановка мест на карте** (`EditRoutPage`)

- кнопка «Назад к описанию» и системная кнопка «Назад» MAX возвращают на шаг 1. Точки хранятся в Store, поэтому при возврате на шаг 2 они снова появляются в списке и на карте;
- карта 2GIS с центром на выбранном городе;
- кнопка «Добавить место» включает режим выбора точки:
  - на компьютере курсор над картой становится меткой;
  - на телефоне кнопка подсвечивается и меняет текст на «Выберите место на карте», над картой появляется подсказка «Нажмите на карту, чтобы поставить метку»;
  - повторное нажатие на кнопку выключает режим;
- после выбора точки открывается окно «Новая точка»: фото (с превью), название (обязательно), средний чек (обязательно, 0 и больше), описание. Кнопки «Сохранить» и «Отмена»;
- список добавленных точек с номерами, синхронизирован с метками на карте;
- кнопка «Сбросить» удаляет все точки;
- кнопка «Скрыть маршрут» / «Показать маршрут», как на карте просмотра;
- кнопка «Опубликовать» (неактивна без точек):
  1. загружает обложку и фото мест на сервер;
  2. отправляет маршрут и места запросом `POST /api/addRoute`;
  3. общая цена считается автоматически как сумма цен мест;
  4. после успеха возвращает к списку маршрутов, при ошибке показывает сообщение.

**Не реализовано:**

- редактирование и удаление уже добавленной точки, перетаскивание метки;
- изменение порядка точек;
- вкладки «День 1» / «День 2» для двухдневных маршрутов;
- категории мест;
- предупреждение при выходе из редактора с несохранёнными данными.

### 3.7 Личный кабинет

**Статус: Не реализовано.**

Страница для управления своими маршрутами и лайками.

**Вход:** иконка профиля в шапке списка маршрутов (3.2). Страница доступна только внутри MAX (нужен id пользователя).

**Шапка:**

- аватар и имя пользователя из MAX Bridge (`initDataUnsafe.user.first_name`, `last_name`, `photo_url`). Если данных нет, показывается заглушка;
- счётчики: число моих маршрутов и сумма лайков, которые они получили;
- кнопка «Назад» к списку маршрутов.

**Вкладки «Мои маршруты» и «Понравившиеся».** Выбранная вкладка хранится в Store.

**Вкладка «Мои маршруты»:**

- маршруты текущего пользователя из всех городов, сначала новые;
- карточка: обложка, название, город, цена, число лайков, дата публикации;
- действия на карточке:
  - «Открыть» - экран маршрута (3.3);
  - «Редактировать» - редактор маршрута (3.6), где все поля и точки уже заполнены. Сохранение отправляет изменения на сервер;
  - «Удалить» - окно подтверждения «Удалить маршрут? Его места и лайки тоже будут удалены.» с кнопками «Удалить» и «Отмена»;
- пагинация по 10, как в списке маршрутов;
- пустое состояние «Вы ещё не создали ни одного маршрута» и кнопка «Создать маршрут».

**Вкладка «Понравившиеся»:**

- маршруты, которые пользователь лайкнул, сначала последние лайкнутые;
- карточка как в списке маршрутов, дополнительно указан город;
- кнопка с сердечком снимает лайк. Карточка исчезает из списка, внизу на 5 секунд появляется уведомление «Лайк снят» с кнопкой «Вернуть»;
- пагинация по 10;
- пустое состояние «Здесь появятся маршруты, которые вам понравились».

**Правила доступа:**

- редактировать и удалять маршрут может только его автор. Сервер проверяет, что `author_id` маршрута совпадает с id пользователя из проверенных данных MAX (раздел 2);
- кабинет включается только при заданном `BOT_TOKEN`, иначе id пользователя можно подделать.

**Что нужно добавить на сервере:**

| Метод | Путь | Параметры | Ответ |
|---|---|---|---|
| GET | `/api/getMyRoutes` | `page`, пользователь из `X-Max-Init-Data` | `{ routes, pagesCount }`, у маршрутов есть `city`, `likes` |
| GET | `/api/getLikedRoutes` | `page`, пользователь из `X-Max-Init-Data` | `{ routes, pagesCount }`, сортировка по времени лайка |
| POST | `/api/updateRoute` | `{ route_guid, route, places }`, пользователь из `X-Max-Init-Data` | guid маршрута |
| POST | `/api/deleteRoute` | `{ route_guid }`, пользователь из `X-Max-Init-Data` | `true` |

Для сортировки понравившихся маршрутов по времени лайка в таблицу `likes` нужно добавить колонку `created_at`. Удаление маршрута удаляет его места и лайки.

### 3.8 Системная кнопка «Назад» MAX

**Статус: Реализовано.**

Хук `client/src/hooks/useMaxBackButton.js` показывает кнопку «Назад» в шапке MAX (`WebApp.BackButton`) и задаёт её действие для каждого экрана:

| Экран | Действие |
|---|---|
| Выбор города | кнопка скрыта |
| Список маршрутов | к выбору города |
| Маршрут | закрывает карточку места, затем карту, затем возвращает к списку |
| Создание, шаг 1 | к списку маршрутов |
| Создание, шаг 2 | закрывает окно новой точки, затем возвращает на шаг 1 |

### 3.9 Бот MAX

**Статус: Реализовано.**

Сервис `bot/` получает обновления через long polling (`GET /updates` MAX Bot API). На запуск бота (`bot_started`) и любое сообщение пользователя (`message_created`, кроме сообщений ботов) отвечает приветствием и кнопкой «Открыть маршруты» со ссылкой `https://max.ru/<BOT_NAME>?startapp=start`. Мини-приложение подключено к этому же боту на платформе MAX.

## 4. Технические требования

### 4.1 Архитектура

**Клиент** (`client/`): React 19 (Create React App).

- `App.js` создаёт сервисы и передаёт их через контексты `StoreContext` и `ServerContext`;
- `pages/PageManager.js` переключает страницы: `START`, `ROUTES`, `CREATE_ROUTE`, `EDIT`, `ROUTE`;
- страницы лежат в `pages/<Страница>/`, их части - во вложенных папках (`CitySearch`, `AddPlaceCart`, `PlaceCard`, `RouteMap`);
- общие компоненты: `components/LikeButton`, `components/RouteToggleButton`, `components/PhotoCredit`;
- сервисы: `Store` (общее состояние), `Server` (запросы к API, передаёт `X-Max-Init-Data`), `Max` (MAX Bridge: пользователь, подпись, параметр запуска, «Поделиться», кнопка «Назад»), `Geo` (геопозиция и ближайший город);
- хук `hooks/useMaxBackButton.js`;
- утилиты: `utils/formatPrice.js`, `utils/getImageUrl.js`;
- настройки в `Config.js` из переменных окружения сборки: адрес API (`REACT_APP_HOST`), адрес статики (`REACT_APP_STATIC_HOST`), ключ 2GIS (`REACT_APP_MAPGL_KEY`), имя бота (`REACT_APP_BOT_NAME`). Ключей в коде нет.

**Сервер** (`server/`): Node.js 22, Express 5.

- `app.js` создаёт БД, медиатор, менеджеры и роутер;
- `application/router/Router.js` и обработчики `handlers/use<Имя>Handler.js`. Обработчик проверяет входные данные (`router/validators.js`) и обращается к менеджеру через медиатор;
- `modules/Mediator` - триггеры `GET_CITIES`, `GET_ROUTES`, `GET_ROUTE`, `GET_PLACES`, `ADD_ROUTE`, `TOGGLE_LIKE`, `GET_USER_ID`;
- `modules/routes/RoutesManager.js` - логика маршрутов, мест и лайков;
- `modules/auth/AuthManager.js` - проверка подписи `initData` MAX (раздел 2);
- `modules/db/DB.js` и `ORM.js` - работа с SQLite;
- `Answer.js` - формат ответов, коды ошибок и их HTTP-статусы;
- настройки в `config.js`: порт (`PORT`), папка базы (`DATABASE_DIR`), токен бота (`BOT_TOKEN`), публикация без id (`ALLOW_ANONYMOUS_ROUTES`), размер страницы, лимиты загрузки.

**Бот** (`bot/`): Node.js 22 без внешних зависимостей, раздел 3.9.

**Обработка ошибок:** конструкция try/catch не используется. Ошибочные ситуации отсекаются проверками: сервер проверяет наличие и тип каждого параметра до обращения к базе, клиент проверяет, что пришёл JSON, и показывает сообщение об ошибке с кнопкой «Повторить». Все ошибки API возвращаются в JSON с HTTP-статусом. Неизвестный путь отвечает 404, ошибки, которые проверками не предотвратить (например, битый JSON в теле запроса), перехватывает обработчик ошибок Express и отвечает 400 или 500, сервер при этом продолжает работать.

**База данных:** SQLite (`data.db`). Таблица городов заполняется из `modules/db/seeds/cities.json` при первом запуске, если она пустая.

**Карты:** 2GIS MapGL JS API (`@2gis/mapgl`) и плагин маршрутов `@2gis/mapgl-directions`. Используются только отображение карты, метки, клик по карте и построение пешеходного маршрута. Данные о местах из карт не берутся.

**Фото:** принимаются сервером через Multer (`POST /api/uploadImage`, поле `image`):

- только JPEG, PNG и WebP до 5 МБ;
- имя файла генерирует сервер, расширение определяется по типу файла, а не по имени от пользователя (защита от загрузки HTML и SVG со скриптами);
- файлы сохраняются в `server/public/uploads`, в базе хранится путь `/uploads/<guid>.<ext>`;
- фото мест для стартовых маршрутов лежат в `server/public/images/places`.

**Подписи к фото:** у маршрутов и мест есть поле `photo_credit` (автор, лицензия, источник). Оно показывается под фото в списке, на экране маршрута и в карточке места, как требуют лицензии CC BY.

**Развёртывание:** Docker Compose, три контейнера (`server`, `client` с nginx, `bot`). Переменные окружения задаются в `.env` по шаблону `.env.example`. Запуск и переменные описаны в `README.md`, установка на сервер в `DEPLOY.md`.

### 4.2 Интеграция с MAX

- **Реализовано:**
  - id пользователя и проверка подписи `initData` (раздел 2);
  - «Поделиться» через `shareMaxContent` и открытие маршрута по параметру запуска `start_param` (3.3, 3.1);
  - системная кнопка «Назад» `BackButton` (3.8);
  - бот с кнопкой открытия мини-приложения (3.9).
- **Не реализовано:** имя и аватар пользователя, подтверждение закрытия во время редактирования (`enableClosingConfirmation`).

### 4.3 Данные и их происхождение

- **Города:** 1117 городов России с координатами и регионом из открытого набора HFLabs (github.com/hflabs/city).
- **Стартовые маршруты:** 15 маршрутов по Москве (51 место) и 10 по Казани (32 места) с описаниями и примерными ценами. Координаты мест взяты из Викиданных, фото с Wikimedia Commons под свободными лицензиями. Авторы и лицензии показываются под фото в интерфейсе и перечислены в `server/public/images/places/CREDITS.md`. То, что это заранее подготовленные тестовые данные, отмечено в README и в интерфейсе («Цены примерные»).
- **Пользовательские маршруты:** все данные о местах вводит автор. Карта используется только как холст и инструмент выбора координат, поэтому сохраняются только координаты клика и то, что ввёл пользователь.

## 5. Модель данных

Координаты везде хранятся так: `x` - долгота, `y` - широта. Первичные ключи - GUID (UUID v4), их генерирует сервер.

```
cities
 - guid        TEXT
 - city        TEXT          название
 - region      TEXT          регион, например «Удмуртская Республика»
 - x, y        REAL          центр города

routes
 - guid        TEXT PK
 - name        TEXT          название маршрута
 - title       TEXT          описание от автора
 - cost        INTEGER       общая цена, сумма цен мест
 - x, y        REAL          центр города маршрута
 - author_id   TEXT          id пользователя MAX
 - photo_url   TEXT          обложка
 - photo_credit TEXT         автор и лицензия фото
 - city_guid   TEXT          -> cities.guid
 - created_at  INTEGER       время создания, мс

places
 - guid        TEXT PK
 - route_guid  TEXT          -> routes.guid
 - name        TEXT
 - x, y        REAL          точка, выбранная автором на карте
 - price       REAL          0 - бесплатно
 - description TEXT
 - photo_url   TEXT
 - photo_credit TEXT
 порядок посещения = порядок добавления

likes
 - route_guid  TEXT          -> routes.guid
 - user_id     TEXT          id пользователя MAX
 PK (route_guid, user_id)
```

**Запланировано:**

- `routes.duration_days` (1 или 2), `places.day_number` и `places.order_index` - для двухдневных маршрутов и изменения порядка мест;
- `places.category` - категория места;
- `routes.author_name` - имя автора из MAX;
- `likes.created_at` - для вкладки «Понравившиеся» в личном кабинете.

## 6. API

Полное описание: `openapi.yaml` (OpenAPI 3.0.3). Обязательные проверки для жюри: `DATA-API.yaml`, тестовые данные: `test-data/test-data.json`.

Все пути начинаются с `/api`.

- Успешный ответ: HTTP 200, `{ "result": "ok", "data": ... }`.
- Ошибка: `{ "result": "error", "error": { "code": 67, "message": "..." } }` с HTTP-статусом из таблицы ниже.
- Пользователь передаётся заголовком `X-Max-Init-Data` (раздел 2). Параметры `user`, `user_id`, `author_id` учитываются, только если на сервере не задан `BOT_TOKEN`.

| Метод | Путь | Параметры | Ответ |
|---|---|---|---|
| GET | `/getCities` | - | список городов |
| GET | `/chooseCity/:city` | - | `true` |
| GET | `/getRoutes` | `city`, `page` (с 1), `sort` (`date` или `likes`) | `{ routes, pagesCount }`, у маршрута есть `likes` и `liked` |
| GET | `/getRoute` | `route` | маршрут с `likes` и `liked` (для ссылки «Поделиться») |
| GET | `/getPlaces` | `route` | места маршрута в порядке посещения |
| POST | `/addRoute` | `{ route: { name, title, cost, x, y, city_guid, photo_url }, places: [{ name, x, y, price, description, photo_url }] }` | guid маршрута |
| POST | `/toggleLike` | `{ route_guid }` | `{ liked, likes }` |
| POST | `/uploadImage` | `multipart/form-data`, поле `image` | путь к файлу |

Размер страницы маршрутов - 10 (`ROUTES.PAGE_SIZE` в `server/config.js`).

**Коды ошибок:**

| Код | HTTP | Текст |
|---|---|---|
| 11 | 401 | Ошибка авторизации (нет пользователя или неверная подпись MAX) |
| 25 | 404 | Маршрут не найден |
| 67 | 400 | Не переданы все необходимые параметры |
| 68 | 400 | Не удалось загрузить изображение |
| 69 | 400 | Некорректное тело запроса |
| 404 | 404 | Метод не найден |
| 9000 | 500 | Внутренняя ошибка сервера |

## 9. Известные ограничения и открытые вопросы

- Без `BOT_TOKEN` сервер доверяет id пользователя из запроса. Это режим локальной разработки, в рабочем запуске `BOT_TOKEN` обязателен.
- Маршрут и его места записываются без транзакции: если запись мест упадёт, маршрут останется без мест.
- Если после загрузки фото публикация не удалась, файлы остаются на сервере без маршрута. Нужна периодическая очистка.
- Если сервер недоступен (нет сети), `fetch` на клиенте завершается ошибкой браузера, которую проверками не предотвратить: данные не загрузятся. При ответе сервера с ошибкой показывается сообщение и кнопка «Повторить».
- Бот при полном сетевом сбое завершает процесс, Docker перезапускает его (`restart: on-failure`). Ответы MAX Bot API с ошибкой бот переживает и повторяет запрос через 5 секунд.
- Отмена пользователем окна «Поделиться» в MAX не обрабатывается отдельно.
- У стартовых маршрутов нет лайков, поэтому сортировка «Популярные» до первых лайков совпадает с «Новыми».
- Цены в стартовых маршрутах примерные (сентябрь 2026), их нужно периодически обновлять.
- Ключ 2GIS встраивается в клиент при сборке и виден в браузере. В кабинете 2GIS ключ нужно ограничить доменом приложения.
