# Маршруты

Мини-приложение MAX для поиска и создания туристических маршрутов по городам России. Трек хакатона «Досуг и развлечения».

## Назначение

Человек приезжает в незнакомый город на 1-2 дня и хочет понять, куда сходить и во сколько обойдётся день. Сейчас для этого приходится собирать маршрут из отзывов, карт и блогов вручную.

В приложении можно:

- выбрать город (ближайший подставляется по геопозиции);
- посмотреть готовые маршруты с общей стоимостью, отсортировать их по новизне или популярности;
- открыть маршрут: описание, места по порядку с ценой и фото, пешеходный маршрут на карте;
- поставить лайк и поделиться маршрутом в чат MAX;
- создать свой маршрут: отметить места на карте, заполнить название, цену, описание, фото и опубликовать.

Подробное описание функций и статусы реализации: [TZ.md](TZ.md).

## Основной пользовательский сценарий

1. Пользователь открывает бота в MAX и нажимает «Открыть маршруты».
2. На экране «Выберите город» уже подставлен ближайший город, либо пользователь вводит название и выбирает его из подсказок.
3. Открывается список маршрутов города по 10 на странице, их можно отсортировать: «Новые» или «Популярные».
4. Пользователь открывает маршрут, видит общую цену, описание и места, открывает «Карту маршрута».
5. Ставит лайк или нажимает «Поделиться», чтобы отправить маршрут в чат. Получатель открывает ссылку и сразу попадает на этот маршрут.

Дополнительный сценарий: кнопка «+» в списке, описание маршрута, расстановка мест на карте, «Опубликовать».

## Состав и архитектура

| Компонент | Папка | Технологии | Роль |
|---|---|---|---|
| client | `client/` | React 19 (Create React App), nginx | Мини-приложение. В Docker nginx отдаёт сборку и проксирует `/api`, `/images`, `/uploads` на сервер |
| server | `server/` | Node.js 22, Express 5, SQLite, Multer | REST API, база, загрузка фото, проверка подписи MAX |
| bot | `bot/` | Node.js 22, без зависимостей | Бот MAX: на запуск и сообщения отвечает приветствием и кнопкой открытия мини-приложения |

```
MAX (мобильный или веб)
   │  бот ── кнопка «Открыть маршруты» ──┐
   ▼                                      ▼
 bot ── MAX Bot API              client (nginx :80) ── /api, /images, /uploads ──► server (:3003) ── SQLite (том server-data)
                                         │                                              └─ фото (том server-uploads)
                                         └── 2GIS MapGL JS API (карты, пешеходные маршруты)
```

**Клиент:**

- `pages/` - экраны (выбор города, список, маршрут, создание, редактор точек);
- `components/` - общие компоненты (лайк, переключатель маршрута, подпись к фото);
- `services/` - сервисы: `Store` (состояние), `Server` (API), `Max` (MAX Bridge), `Geo` (геопозиция);
- `hooks/useMaxBackButton.js` - системная кнопка «Назад» MAX;
- `Config.js` - настройки из переменных окружения.

**Сервер:**

- `application/router` - маршруты API, обработчики и проверка входных данных;
- `modules/Mediator` - связь обработчиков с логикой через триггеры;
- `modules/routes/RoutesManager.js` - маршруты, места, лайки;
- `modules/auth/AuthManager.js` - проверка подписи `initData` MAX;
- `modules/db` - SQLite и ORM, заполнение городов при первом запуске.

Контракт API: [openapi.yaml](openapi.yaml). Обязательные проверки API: [DATA-API.yaml](DATA-API.yaml).

## Запуск через Docker

```bash
cp .env.example .env    # заполните значения, см. ниже
docker compose up -d --build
```

Приложение откроется на `http://localhost:8080`. В сборке выполняются только установка зависимостей по `package-lock.json` и сборка клиента, без компиляции нативных модулей.

Для работы внутри MAX нужен HTTPS: установка на сервер с доменом и сертификатом описана в [DEPLOY.md](DEPLOY.md).

### Переменные окружения

Задаются в файле `.env` в корне проекта (шаблон: [.env.example](.env.example)).

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `MAPGL_KEY` | да | - | Ключ 2GIS MapGL JS API. Без него карты не загрузятся. Встраивается в клиент при сборке |
| `BOT_TOKEN` | для работы в MAX | - | Токен бота MAX. Нужен боту и серверу для проверки подписи пользователя. Без него сервер доверяет id из запроса (режим разработки) |
| `BOT_NAME` | для работы в MAX | - | Ник бота без `@`. Нужен для ссылок «Поделиться» и кнопки в боте. Без него кнопка «Поделиться» скрыта |
| `ALLOW_ANONYMOUS_ROUTES` | нет | `false` | `true` разрешает публикацию маршрутов без пользователя MAX (автор `anonymous`). Только для тестирования |
| `CLIENT_PORT` | нет | `8080` | Порт клиента на `127.0.0.1` |

Внутренние переменные контейнеров (менять не нужно): `PORT=3003` и `DATABASE_DIR=/app/data` у сервера, `REACT_APP_HOST=/api` и `REACT_APP_STATIC_HOST=""` при сборке клиента.

### Порты

| Порт | Где | Назначение |
|---|---|---|
| `127.0.0.1:8080` | хост | Клиент и проксируемый API (`/api`) |
| `3003` | внутри сети Docker | API сервера, наружу не публикуется |

Бот работает через исходящие запросы к MAX Bot API и портов не открывает.

### Остановка и повторный запуск

```bash
docker compose stop        # остановить
docker compose start       # запустить снова
docker compose restart     # перезапустить
docker compose down        # остановить и удалить контейнеры, данные в томах сохраняются
docker compose up -d       # запустить после down
docker compose up -d --build   # пересобрать после изменения кода или .env
docker compose logs -f server  # логи API
```

## Запуск без Docker (разработка)

```bash
cd server && npm ci && node app.js     # API на http://localhost:3003
cd client && npm ci && npm start       # клиент на http://localhost:3000
cd bot && BOT_TOKEN=... BOT_NAME=... node index.js
```

Для клиента создайте `client/.env.local` с `REACT_APP_MAPGL_KEY=<ключ>`. Вне MAX при `npm start` подставляется тестовый пользователь `dev-user`, а сервер без `BOT_TOKEN` принимает его id.

## Зависимости

Версии зафиксированы в `package-lock.json` каждого компонента.

- **server:** `express`, `cors`, `multer`, `sqlite3`;
- **client:** `react`, `react-dom`, `react-scripts`, `@2gis/mapgl`, `@2gis/mapgl-directions` (BSD-2-Clause);
- **bot:** без внешних зависимостей;
- **образы:** `node:22-bookworm-slim` (server), `node:22-alpine` (сборка client и bot), `nginx:1.27-alpine` (client).

## Внешние сервисы и интеграции

| Сервис | Для чего | Что нужно |
|---|---|---|
| MAX Bridge (`https://st.max.ru/js/max-web-app.js`) | id и подпись пользователя (`initData`), параметр запуска для ссылок, «Поделиться» (`shareMaxContent`), кнопка «Назад» (`BackButton`) | Мини-приложение подключено к боту на платформе MAX |
| MAX Bot API (`https://platform-api2.max.ru`) | Бот: получение обновлений и отправка приветствия с кнопкой | `BOT_TOKEN`, `BOT_NAME` |
| 2GIS MapGL JS API и Directions API | Карта, метки, пешеходный маршрут между местами | `MAPGL_KEY`. Если ключ ограничен по доменам, домен приложения добавлен в кабинете 2GIS |
| Геолокация браузера (`navigator.geolocation`) | Выбор ближайшего города. В MAX Bridge метода геолокации нет | Разрешение пользователя, HTTPS |

Внутри Docker воспроизводятся все компоненты, кроме самих MAX и 2GIS: без доступа к ним карта не загрузится, а бот и проверка подписи работать не будут. Остальные сценарии (города, маршруты, места, лайки в режиме разработки) проверяются локально.

## Работа с данными

- **Хранение:** SQLite, файл `data.db`. В Docker он лежит в томе `server-data`, загруженные фото в томе `server-uploads`.
- **Модель данных:**
  - `cities` - города;
  - `routes` - маршруты: название, описание, цена, автор, город, фото с подписью, дата;
  - `places` - места маршрута: координаты, цена, описание, фото с подписью;
  - `likes` - лайки: маршрут и пользователь.

  Подробности в [TZ.md](TZ.md), раздел 5.
- **Пользователь:** id пользователя MAX. Если задан `BOT_TOKEN`, сервер принимает id только из `initData` с проверенной подписью (HMAC-SHA256, срок действия 24 часа). Персональные данные, кроме id, не хранятся.
- **Фото:** принимаются только JPEG, PNG и WebP до 5 МБ, имя файла генерирует сервер.
- **Проверка ввода:** сервер проверяет наличие и тип каждого параметра до обращения к базе. Ошибки возвращаются в JSON с HTTP-кодами 400, 401, 404, 500.

## Тестовые данные

**Все маршруты, места и цены в поставке - заранее подготовленные тестовые данные, а не интеграция с внешней системой.**

- **Города:** 1117 городов России с координатами и регионами из открытого набора [HFLabs](https://github.com/hflabs/city) (`server/application/modules/db/seeds/cities.json`). Загружаются в пустую базу при первом запуске.
- **Маршруты:** 15 маршрутов по Москве (51 место) и 10 по Казани (32 места) составлены командой вручную.
  - Координаты мест взяты из Викиданных.
  - Цены примерные, на сентябрь 2026 года. В интерфейсе это отмечено надписью «Цены примерные и указаны автором маршрута».
  - Фото взяты с Wikimedia Commons под свободными лицензиями. Автор и лицензия показываются под каждым фото и перечислены в `server/public/images/places/CREDITS.md`.
  - Лайков у стартовых маршрутов нет.
- **Где лежат данные:** в `server/application/modules/db/data.db`. При первом запуске Docker база копируется в том, дальнейшие изменения сохраняются только в томе. Чтобы вернуться к исходным данным, удалите том: `docker compose down && docker volume rm <папка>_server-data`.
- **Файлы для проверки API:**
  - [test-data/test-data.json](test-data/test-data.json) - guid городов и маршрутов, тестовые пользователи, пример тела `addRoute`;
  - `node test-data/make-init-data.js <BOT_TOKEN> [user_id]` - подписанная строка `initData` для заголовка `X-Max-Init-Data`, если нужно проверить API без клиента MAX.

## Примеры ожидаемого поведения API

```bash
curl http://localhost:8080/api/getRoutes?city=2f8f462b-7bf7-4c9c-8796-7a1afe7d13c4
# 200 {"result":"ok","data":{"routes":[...10 маршрутов...],"pagesCount":1}}

curl http://localhost:8080/api/getRoutes
# 400 {"result":"error","error":{"code":67,"message":"Не переданы все необходимые параметры"}}

curl -X POST http://localhost:8080/api/toggleLike -H 'Content-Type: application/json' \
  -d '{"route_guid":"f3dda26b-0b7a-4d09-95bb-3abe8afb49dc"}'
# 401 {"result":"error","error":{"code":11,"message":"Ошибка авторизации"}}

curl -X POST http://localhost:8080/api/toggleLike -H 'Content-Type: application/json' \
  -H "X-Max-Init-Data: $(node test-data/make-init-data.js "$BOT_TOKEN")" \
  -d '{"route_guid":"f3dda26b-0b7a-4d09-95bb-3abe8afb49dc"}'
# 200 {"result":"ok","data":{"liked":true,"likes":1}}
```

## Известные ограничения

- **Функции, которых пока нет:**
  - личный кабинет (мои маршруты и лайки, редактирование и удаление маршрутов) описан в [TZ.md](TZ.md), раздел 3.7;
  - в редакторе нельзя изменить или удалить отдельную точку и поменять порядок точек;
  - поле «Длительность» не сохраняется, двухдневные маршруты не поддерживаются;
  - категорий мест нет.
- **Без `BOT_TOKEN`** сервер доверяет id пользователя из запроса. Это режим разработки, в рабочем запуске `BOT_TOKEN` обязателен.
- **Недоступный сервер или сеть:** запрос с клиента завершается ошибкой браузера, и данные не загружаются. При ответе сервера с ошибкой показывается сообщение и кнопка «Повторить».
- **Бот и сетевой сбой:** бот при недоступности MAX Bot API повторяет запрос через 5 секунд. При полном сетевом сбое процесс завершается, и Docker перезапускает его (`restart: on-failure`).
- **Публикация маршрута:**
  - маршрут и его места записываются без транзакции;
  - фото, загруженные при неудачной публикации, остаются на сервере.
- **Цены и `MAPGL_KEY`:**
  - цены в стартовых маршрутах примерные и требуют периодического обновления;
  - ключ `MAPGL_KEY` встраивается в клиентский код при сборке и виден в браузере, так устроены все клиентские карты. Ограничьте ключ доменом приложения в кабинете 2GIS.
