# Маршруты

Мини-приложение с чат-ботом в MAX для поиска и создания туристических маршрутов по городам России. Трек хакатона «Досуг и развлечения».

Документация актуализирована 29.09.2026 по исходному коду, конфигурации и поставляемой базе. Требования к материалам и проверке взяты из PDF «Досуг и развлечения», стр. 6-10, 12-17. Наличие реализации в коде не означает, что уже подтверждена работа опубликованного приложения в MAX.

## Назначение и аудитория

Приоритетный пользователь - турист, впервые приехавший в Казань на один день, который хочет выбрать прогулку и заранее оценить расходы на посещение мест. Дополнительный сегмент - жители города, выбирающие прогулку на выходной.

Проблема: маршрут приходится собирать из карт, отзывов и описаний отдельных мест, отдельно уточняя цены. Это продуктовая гипотеза команды: в репозитории нет результатов интервью или исследования, подтверждающих величину проблемы. Перед пилотом её следует проверить на целевом сегменте.

Результат в MVP: пользователь получает последовательность мест с описаниями, примерными ценами и отображением на карте. Стоимость маршрута - сумма цен мест; транспорт, проживание и другие расходы автоматически не учитываются. В текущей версии нет расписаний, проверки доступности объектов и расчёта времени прогулки.

## Основной пользовательский сценарий

1. Открыть чат-бота в MAX и нажать «Открыть маршруты».
2. Выбрать Казань через поиск с подсказками. При разрешённой геолокации приложение может подставить ближайший город.
3. Выбрать готовый маршрут из списка, сравнив названия, обложки и примерную стоимость.
4. Открыть описание маршрута и карточки мест, затем «Карту маршрута» с метками и пешеходной линией между точками.
5. Получить план прогулки. Дополнительно можно поставить лайк или отправить ссылку на маршрут в чат MAX.

Дополнительный сценарий: в списке нажать «+», заполнить описание, добавить места на карте с ценами и опубликовать маршрут. Подробности реализации, API и критерии приёмки: [TZ.md](TZ.md).

## Реализованные функции

- Поиск города с подсказками и регионами, автовыбор ближайшего города через геолокацию браузера.
- Список маршрутов города, сортировка «Новые» и «Популярные», страницы по 10 маршрутов.
- Просмотр маршрута и мест, фотографий и подписей к ним, примерной стоимости и даты публикации.
- Карта 2GIS с пронумерованными метками при просмотре и пешеходным маршрутом; линию можно скрыть.
- Создание маршрута, добавление точек, общий сброс точек, загрузка обложки и фото мест.
- Лайки, серверная проверка подписи MAX при заданном `BOT_TOKEN`, системная кнопка «Назад».
- Отправка ссылки через `shareMaxContent` и обработка `start_param=route_<guid>` реализованы в коде; прохождение между двумя пользователями MAX требует отдельной проверки.

Длительность «1 день / 2 дня» видна в форме, но не сохраняется и не влияет на маршрут. Личного кабинета, изменения опубликованного маршрута и редактирования отдельных точек нет.

## Состав и архитектура

| Компонент | Технологии | Назначение |
|---|---|---|
| `client/` | React 19, Create React App, 2GIS MapGL, nginx | Интерфейс мини-приложения; nginx отдаёт сборку и проксирует `/api/`, `/images/`, `/uploads/` |
| `server/` | Node.js 22, Express 5, SQLite (`sqlite3`), Multer | REST API, хранение маршрутов и лайков, загрузка изображений, проверка `initData` |
| `bot/` | Node.js 22, без внешних зависимостей | Получает обновления MAX через long polling; отвечает приветствием и ссылкой открытия мини-приложения |

```text
MAX -> бот -> кнопка открытия -> client (nginx:80)
                                 |-> MAX Bridge
                                 |-> 2GIS MapGL / Directions
                                 `-> /api -> server:3003 -> SQLite
                                         `-> /uploads -> фотографии
```

Клиентские экраны находятся в `client/src/pages`, состояние текущей сессии - в `services/Store`, обращения к API - в `services/Server`, интеграция MAX - в `services/Max`. Серверные обработчики находятся в `server/application/router/handlers`, бизнес-логика - в `modules/routes`, авторизация - в `modules/auth`, SQLite и ORM - в `modules/db`.

Контракт: [openapi.yaml](openapi.yaml). Обязательные проверки API: [DATA-API.yaml](DATA-API.yaml). Развёртывание HTTPS: [DEPLOY.md](DEPLOY.md).

## Окружение и запуск через Docker

Нужны Docker Engine с Docker Compose v2 либо Docker Desktop, свободный локальный порт 8080 и доступ в интернет для загрузки образов, зависимостей и внешних сервисов. Образы используют Node.js 22 и nginx. PDF требует сборку не дольше 5 минут без первоначальной загрузки базовых образов; длительность нужно измерить на машине проверки. Здесь Docker-сборка не запускалась.

В корне проекта скопируйте [.env.example](.env.example) в `.env` и заполните значения. В PowerShell:

```powershell
Copy-Item .env.example .env
```

Одна команда запуска всех локальных компонентов после заполнения `.env`:

```sh
docker compose up -d --build
```

Клиент и API доступны через `http://localhost:8080` и `http://localhost:8080/api`. Для работы внутри MAX нужен публичный HTTPS-адрес, подключённый к боту в настройках платформы. Локальный запуск не заменяет доступный продукт в MAX.

### Переменные окружения

| Переменная в корневом `.env` | Требование / значение по умолчанию | Назначение |
|---|---|---|
| `MAPGL_KEY` | Нужен для карт | Ключ для MapGL и пешеходных маршрутов; встраивается в клиент при сборке |
| `BOT_TOKEN` | Нужен для бота и защищённых действий в MAX | Токен одного и того же бота у `bot` и `server`; без него сервер доверяет переданному id пользователя |
| `BOT_NAME` | Нужен для бота и отправки ссылок | Ник бота без `@`; используется в ссылках `https://max.ru/<BOT_NAME>?startapp=...` |
| `ALLOW_ANONYMOUS_ROUTES` | `false` | При `true` сервер разрешает публикацию без подтверждённого пользователя с автором `anonymous`; для рабочего запуска оставить `false` |
| `CLIENT_PORT` | `8080` | Порт клиента на `127.0.0.1` |

В контейнере сервера заданы `PORT=3003`, `DATABASE_DIR=/app/data`. При сборке клиента Compose передаёт `REACT_APP_HOST=/api`, `REACT_APP_STATIC_HOST=""`, `REACT_APP_MAPGL_KEY` и `REACT_APP_BOT_NAME`.

Рабочие токены, пароли и ключи не добавляются в исходный код, README или `.env.example`. Значения для проверки передаются организаторам на служебном первом слайде презентации, как указано в PDF. Ключ карты виден в собранном клиенте: ограничьте его доменом приложения и проверьте правила выдачи и использования в 2GIS.

### Порты

| Адрес / порт | Назначение |
|---|---|
| `127.0.0.1:8080` (либо `CLIENT_PORT`) | Клиент, API и изображения через nginx |
| `server:3003` в сети Compose | API; наружу порт не опубликован |
| Публичный HTTPS, обычно 443 | Внешний прокси для доступа из MAX, настраивается отдельно |

Бот принимает обновления исходящими запросами и входящих портов не открывает.

### Остановка и повторный запуск

```sh
docker compose stop
docker compose start
docker compose restart
docker compose down
docker compose up -d
docker compose up -d --build
docker compose logs -f server
```

`stop/start` останавливают и возобновляют существующие контейнеры. `down` удаляет контейнеры и сеть, сохраняя именованные тома; после него используйте `up -d`. После изменения кода или переменных сборки клиента используйте `up -d --build`.

## Запуск без Docker для разработки

Нужны Node.js 22 и npm. Запускайте компоненты в отдельных терминалах из корня проекта.

Сервер:

```powershell
Set-Location server
npm ci
node app.js
```

Клиент:

```powershell
Set-Location client
npm ci
npm start
```

В `client/.env.local` задайте `REACT_APP_MAPGL_KEY=<ключ>`; при необходимости также `REACT_APP_BOT_NAME=<ник>`. API по умолчанию `http://localhost:3003/api`, клиент - `http://localhost:3000`. Корневой `.env` автоматически используется Compose, но не читается обычным `node app.js`.

Для локальной разработки вне MAX сервер запускается без `BOT_TOKEN`, клиент при `npm start` подставляет `dev-user`. Это позволяет проверить лайки и публикацию. Продакшен-сборка в обычном браузере тестового пользователя не подставляет.

Бот, в отдельном PowerShell-терминале:

```powershell
Set-Location bot
$env:BOT_TOKEN = '<токен>'
$env:BOT_NAME = '<ник без @>'
node index.js
```

## Зависимости и внешние сервисы

Версии фиксируются в `server/package-lock.json`, `client/package-lock.json`, `bot/package-lock.json`. Dockerfile использует `npm ci`; серверный `sqlite3` - нативная зависимость, поэтому при отсутствии подходящего готового бинарного файла установка может потребовать сборки. Нельзя заранее гарантировать отсутствие компиляции.

- Сервер: `express`, `cors`, `multer`, `sqlite3`.
- Клиент: `react`, `react-dom`, `react-scripts`, `@2gis/mapgl`, `@2gis/mapgl-directions`, `web-vitals`; остальные зависимости и инструменты перечислены в `client/package.json`.
- Бот: стандартные средства Node.js, включая `fetch`.
- Образы: `node:22-bookworm-slim`, `node:22-alpine`, `nginx:1.27-alpine`.

| Внешний сервис | Назначение и условия проверки |
|---|---|
| MAX Bridge, `https://st.max.ru/js/max-web-app.js` | Данные запуска, отправка ссылки, системная кнопка «Назад»; требуется запуск мини-приложения из подключённого бота |
| MAX Bot API, `https://platform-api2.max.ru` в коде бота | Получение обновлений и приветствие; нужны действующий токен и сеть. Доступность указанного адреса и соответствие текущему API проверить перед сдачей |
| 2GIS MapGL и Directions | Отображение карт и пешеходная линия; нужен ключ с доступом к обоим сервисам и разрешённым доменом |
| Геолокация браузера | Необязательная подстановка ближайшего города; нужно разрешение пользователя и защищённый контекст (HTTPS либо localhost) |

Эти внешние платформы не воспроизводятся внутри Docker. Без MAX локально можно проверять просмотр данных, а в режиме разработки - лайки и создание. Без доступа к 2GIS и ключа невозможно полностью проверить карты и редактор точек.

Официальные источники интеграции: [подключение мини-приложения](https://dev.max.ru/docs/webapps/introduction), [MAX Bridge](https://dev.max.ru/docs/webapps/bridge), [валидация данных](https://dev.max.ru/docs/webapps/validation). Перед сдачей сверить используемые методы и [историю изменений](https://dev.max.ru/docs/changelog-platform).

## Работа с данными и тестовая поставка

**Маршруты, места и цены в поставке - заранее подготовленные демонстрационные данные. Автоматического подключения к туристическому каталогу, актуальным ценам или расписаниям нет.**

Проверенная поставляемая база `server/application/modules/db/data.db` содержит:

| Данные | Количество |
|---|---:|
| Города | 1117 |
| Маршруты Москвы / места | 15 / 51 |
| Маршруты Казани / места | 10 / 32 |
| Всего маршрутов / мест | 25 / 83 |
| Лайки | 0 |

Города при пустой таблице загружаются из `server/application/modules/db/seeds/cities.json`. Предыдущая документация называла источником справочника HFLabs, координат мест - Викиданные; отдельного подтверждения происхождения и даты актуальности этих данных в проекте нет, поэтому их нужно проверить перед публикацией материалов.

Фотографии находятся в `server/public/uploads`, ссылки в базе имеют вид `/uploads/<имя>.jpg`. У всех 25 маршрутов и 83 мест в поставляемой базе заполнено `photo_credit` с указанием авторов, лицензий и Wikimedia Commons; интерфейс выводит эти подписи. Отдельного `CREDITS.md` и каталога `server/public/images/places` сейчас нет. Полноту источников и соблюдение лицензий необходимо проверить отдельно. Форма создания не позволяет задать подпись автора фото.

Координаты: `x` - долгота, `y` - широта. Пользовательские места вводятся вручную, карта даёт координаты клика. SQLite хранит города, маршруты, места и лайки; из данных пользователя сохраняется id MAX. Черновик существует только в памяти клиента и теряется после перезагрузки.

При первом запуске Docker `docker-entrypoint.sh` копирует исходную базу в `server-data`, если файла базы там ещё нет. Стартовые фото копируются в `server-uploads`, если файлов с такими именами там нет. Изменения базы и загруженные фото сохраняются в томах; пересборка не возвращает базу к исходному состоянию.

Для воспроизводимой проверки лучше использовать отдельный набор томов с именем проекта:

```sh
docker compose -p tourist-check up -d --build
```

Предварительно остановите другой экземпляр, использующий тот же `CLIENT_PORT`. Полный сброс **только тестового экземпляра** удалит его маршруты, лайки и загруженные изображения:

```sh
docker compose -p tourist-check down -v
docker compose -p tourist-check up -d
```

Для обычного рабочего экземпляра `down -v` не применять, если данные нужно сохранить.

Данные и примеры запросов: [test-data/test-data.json](test-data/test-data.json). Для API доступны гостевой просмотр и роль `max_user`; отдельных логинов и паролей нет. `node test-data/make-init-data.js <BOT_TOKEN> [user_id]` генерирует тестовый заголовок `X-Max-Init-Data` для сервера с тем же токеном. Это средство проверки API, которое не заменяет вход настоящего пользователя MAX.

## Пошаговая проверка и ожидаемое поведение

Сценарий рассчитан на исходную базу; число карточек изменится после публикаций. Повторить основной путь отдельно в мобильной и веб-версии MAX.

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Запустить компоненты, открыть подключённого бота в MAX | Приветствие и кнопка «Открыть маршруты» |
| 2 | Открыть мини-приложение | Выбор города; после разрешения геолокации возможна подстановка ближайшего города |
| 3 | Ввести «Каз», выбрать Казань и нажать «Далее» | 10 маршрутов, стоимость, обложки, лайки; при загрузке виден индикатор |
| 4 | Открыть «Казанский кремль» | Описание, цена, дата и четыре места |
| 5 | Открыть карточку места и «Показать на карте» | Карточка с фото и описанием; карта с центром на выбранном месте |
| 6 | Открыть карту всего маршрута и скрыть линию | Пронумерованные метки; пешеходная линия скрывается, метки остаются |
| 7 | Вернуться кнопками интерфейса и системной «Назад» | Карточка, карта и маршрут закрываются последовательно |
| 8 | Поставить лайк, затем снять его | Состояние и счётчик меняются; повторное нажатие возвращает исходное число |
| 9 | Выбрать «Популярные» | Сначала маршруты с большим числом лайков; при равенстве - более новые |
| 10 | Сменить город на Москву и открыть вторую страницу | В исходной базе 10 маршрутов на первой странице и 5 на второй |
| 11 | «Поделиться», отправить в чат, открыть получателем | Открывается именно переданный маршрут; проверить в MAX двумя пользователями |
| 12 | «+», название и описание, «Далее» | Редактор точек на карте выбранного города |
| 13 | Добавить две точки с названием и ценой, при желании фото | Точки в списке и на карте, пешеходная линия; сумма цен вычисляется клиентом |
| 14 | «Опубликовать» | Возврат в список; маршрут найти при сортировке «Новые» на первой странице |
| 15 | Перезапустить контейнеры и открыть маршрут | Маршрут, места, лайки и фото сохранились |
| 16 | Отклонить доступ к геолокации | Выбор города вручную остаётся доступен |

Публикация сохраняет выбранную сортировку и страницу, поэтому новый маршрут не обязательно сразу будет виден: выберите «Новые» и первую страницу.

Примеры запросов (в PowerShell использовать `curl.exe`):

```sh
curl "http://localhost:8080/api/getRoutes?city=2f8f462b-7bf7-4c9c-8796-7a1afe7d13c4&page=1&sort=date"
# HTTP 200: result=ok, data.routes содержит 10 маршрутов, data.pagesCount=1

curl "http://localhost:8080/api/getRoute?route=f3dda26b-0b7a-4d09-95bb-3abe8afb49dc"
# HTTP 200: result=ok, data.name="Казанский кремль"

curl "http://localhost:8080/api/getRoutes"
# HTTP 400: result=error, error.code=67

curl "http://localhost:8080/api/getRoute?route=missing-route"
# HTTP 404: result=error, error.code=25
```

На сервере с `BOT_TOKEN` публикация и лайки без действительного `X-Max-Init-Data` получают 401 при корректном теле запроса и выключенном `ALLOW_ANONYMOUS_ROUTES`. Ограничение изображения свыше 5 МБ, неподдерживаемого MIME-типа или отсутствующего поля `image` возвращает 400 с кодом 68.

## Известные ограничения

- Нет кабинета, изменения и удаления опубликованных маршрутов, категорий, фильтров по бюджету/длительности, отзывов, бронирования и оплаты.
- Нельзя изменить, удалить или переставить отдельную точку. В редакторе метки не пронумерованы; номера есть в списке и на карте просмотра.
- Длительность не сохраняется; группировки по дням и отдельного третьего шага создания нет, хотя форма показывает «Шаг 1 из 3».
- API проверяет основные типы полей, но не диапазоны координат, неотрицательность цен, существование города и соответствие общей цены сумме мест. Сумму считает клиент.
- Маршрут и места записываются без общей транзакции. После неудачной публикации загруженные фото остаются на сервере.
- Загрузка фото доступна без авторизации; проверяется MIME-тип из запроса, а не фактическое содержимое файла. Нет квот на число файлов и маршрутов.
- Без `BOT_TOKEN` можно подставить id из запроса. `ALLOW_ANONYMOUS_ROUTES=true` допускает публикацию без подтверждённого id даже при заданном токене.
- Проверка `auth_date` ограничивает возраст 24 часами, но не отклоняет дату из будущего. Истечение данных требует повторного открытия мини-приложения.
- В `Server.request` нет обработки отклонения `fetch`: при сетевом сбое индикатор загрузки или публикации может остаться активным. «Повторить» есть для списков городов и маршрутов при обработанном ответе с ошибкой, но не для всех экранов.
- Полный сетевой сбой может завершить бота; Compose перезапускает его. При HTTP-ошибке Bot API polling повторяется через 5 секунд.
- Геолокация необязательна; доступность карт, прокладки пути и отправки ссылки зависит от внешних сервисов. Отмена отправки ссылки отдельно не обрабатывается.
- Для большинства городов готовых маршрутов нет. Достоверность цен, координат и прав на фото не подтверждается автоматически.

## Пилот, ожидаемый эффект и масштабирование

Предлагаемый пилот - однодневные прогулки по Казани. До запуска проверить описания, стоимость и права на изображения, договориться с туристическим инфоцентром или авторами локальных маршрутов (партнёрства пока не подтверждены), предоставить доступ через ссылку/QR-код бота.

Гипотеза эффекта: пользователю потребуется меньше времени, чтобы выбрать прогулку с понятным бюджетом. В пилоте вручную измерять время до выбора маршрута, долю прошедших основной сценарий без помощи, долю открывших карту, успешность переходов по отправленной ссылке и оценку понятности стоимости. Аналитика этих метрик сейчас не реализована, результатов и подтверждённых улучшений нет.

Для переноса в другой город код каталога, просмотра, лайков и создания можно использовать повторно; нужны проверенные местные маршруты, цены, координаты, разрешённые фото и ответственный за обновление. После пилота в Казани сравнить запуск на другом городе (например, Самаре) и только затем расширять каталог. При росте нагрузки потребуются измерения производительности, модерация, резервное копирование и усиление серверных проверок; необходимость замены SQLite определяется измерениями.
